## Подтверждённые проблемы и исправления

1. **Защита прогресса, высокий приоритет.** `recordChapterScan` выполнял
   read/modify/write всего JSON библиотеки. Между чтением и записью другой
   isolate мог сохранить новую страницу, которую фоновая запись затем затирала.
   Метаданные сканирования теперь записываются транзакционно в отдельную
   таблицу существующей SQLite БД и объединяются при загрузке библиотеки.
   Сканер больше не записывает JSON с прогрессом. Прежние поля сохраняются;
   обновление схемы v1 → v2 только добавляет таблицу. Профиль и ID источника
   входят в ключ. Это устраняет именно фоновую перезапись; все возможные
   гонки между самостоятельными действиями UI этим аудитом не доказаны.
2. **Пропуски после задержки.** При первом сканировании проверялись только
   две недавние главы, но остальные кандидаты тоже становились «известными».
   После 36 часов механизм восстановления уже не находил их. Отложенные
   кандидаты теперь остаются непроверенными и доставляются следующим запуском.
3. **Открытая главная лента.** После архивации SQLite-записи старая подсказка
   «Новая глава» возвращалась из кэша. Главная теперь отображает актуальный
   снимок SQLite, без повторного добавления скрытой записи из памяти.
4. **Смена аккаунта.** Payload системного уведомления не содержал профиль,
   поэтому старое уведомление могло открыть одноимённую книгу другого UID.
   Новые уведомления и их ID привязаны к профилю; переход проверяет профиль
   до и после сети. Старые payload без UID разрешены только гостю, поскольку
   их принадлежность доказать невозможно. Открытие из внутренней ленты также
   прерывается при смене профиля во время запроса.

  ограниченных запусков с пересозданием worker-библиотеки, без дублей и

  Открытая главная получает фоновую SQLite-запись при опросе; архивация

- Python-проверки подготовки Android/подписи и экспорта старой библиотеки
  прошли. PowerShell отсутствует локально; соответствующий шаг успешен
  в указанном релизном run.
- `flutter analyze`: компиляционных ошибок нет; остаются прежние замечания

## Обязательная проверка на телефоне

1. На подписанном APK включить внутренние обновления, запретить системные
   уведомления. Закрыть UI удалением из recent apps; дождаться нового
   background run и проверить новые записи SQLite при следующем открытии.
   Сопоставить JobScheduler/WorkManager и время сканирования с логами устройства.
2. Проверить Doze, battery-not-low, отсутствие сети, перезагрузку и ограничения
   производителя. Период 15 минут — минимальный запрошенный интервал,
   не срок доставки. Doze/OEM могут значительно отложить задачу.
3. Отдельно проверить принудительную остановку через Android Settings:
   выполнение до ручного запуска не обещается. После ручного запуска
   проверить catch-up. Сам факт регистрации WorkManager в коде не доказывает
   выполнение после закрытия приложения на конкретном устройстве.
4. Прервать процесс во время HTTP/после inbox commit, затем проверить
   продолжение после истечения lease и отсутствие пропущенных глав/дублей.
5. Менять UID во время сканирования и открытия уведомления, сохранять страницу
   параллельно проверке, оставить главную/inbox открытыми во время реального
   фонового обновления. Проверить запуск по системному уведомлению из
   полностью закрытого приложения и обновление APK поверх установленного.

Исправления находятся только в draft PR. До его принятия опубликованный
APK на `a4125dc` сохраняет перечисленные проблемы.
