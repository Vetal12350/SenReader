# Чтение, источники и уведомления

У каждой книги по-прежнему один активный `preferredSource`, но меню ручного
выбора источника больше нет. Для новой книги без сохранённой позиции SenReader
сравнивает последние **числовые** главы двух достоверно совпавших источников.
Переход возможен только к большей главе с проверенным публичным HTTPS-списком
страниц. Количество строк в списке глав не является критерием. При неясном
номере, равенстве и сетевой ошибке источник не меняется. Для уже читаемой книги
сохранённая позиция и история не переносятся между переводами.

Подключение второго источника выполняется автоматически только при точном
совпадении нормализованного названия. Два сайта не становятся двумя
независимыми закладками. ReadManga остаётся доступной и отображается по имени в каталоге,
поиске и уведомлениях. ReManga в интерфейсе не показываем. Исторические
данные ReManga сохраняются в файлах и локальной библиотеке, но её адаптер
удалён. Никакое содержание платных или недоступных глав не обходится.

При загрузке старой `senreader.library.v1` предпочтение берётся из `lastSource`,
если этот источник известен книге, иначе порядок — Senkuro, ReadManga,
затем прочие ключи по алфавиту. Новые поля совместимы с JSON-переносом библиотеки.
`lastSource` остаётся источником сохранённой позиции, а не текущим предпочтением.
После смены источника старые ID глав и страницы не применяются к новой версии.
Если вернуться к прежнему источнику до сохранения новой позиции, старое место
чтения снова доступно. Сохраняется одна последняя позиция на книгу.

Открытый глаз означает завершённую главу, перечёркнутый — незавершённую. Нажатие
на глаз не открывает читалку. Отметка главы включает её и все доступные главы
этого источника с меньшим или равным числовым номером тома/главы независимо от
сортировки списка. Сначала сравниваются тома, затем главы, включая дробные номера;
отсутствующий том считается нулевым. Для названий без распознаваемого номера
отмечается только выбранная глава, по ID источника. Снятие отметки снимает только
выбранную главу. Сохранение страницы не завершает главу; ни отметка, ни её снятие
не меняют текущую страницу, даже при действии над другой главой.

Ключи завершения теперь содержат источник. Старые числовые ключи при миграции
относятся к прежнему известному `lastSource`. Если установить исходный источник
невозможно, ключи сохраняются без показа отметок на предположительно другом сайте.
Исходные ключи сохраняются для совместимости, но
повторно не интерпретируются (`readHistoryVersion: 2`). Legacy-запись только
последней завершённой главы тоже сохраняется. Отметки разных источников
не смешиваются, даже если номера глав одинаковы.

Внизу читалки есть список глав, предыдущая/следующая глава, счётчик страниц и
глаз для завершения/снятия отметки. Переходы используют доступные главы с
распознаваемыми числовыми номерами; для остальных работает список глав.
Панель занимает отдельное место с SafeArea и не перекрывает изображения.
Настройки читалки, которых приложение пока не поддерживает, не показываются.

Уведомления выключены по умолчанию. Предложение «Включить уведомления о новых
главах?» показывается один раз; отказ, закрытие и отказ Android не приводят к
повторному автоматическому запросу. Флаг предложения хранится отдельно от
включения уведомлений. Позже включить их можно через шестерёнку «Настройки».
Разрешение Android запрашивается только после явного «Включить» или переключения
в настройках. Библиотека содержит только книги и фильтры статуса.

Фоновые и ручные проверки используют один алгоритм: проверяются оба доступных
источника, но только если соответствие тайтлов подтверждено точным названием.
У каждого источника собственный baseline первого успешного сканирования,
`initializedSources` и `sourceSeenChapterKeys`. Общая коллекция
`seenChapterKeys` запрещает повторное уведомление о той же распознанной
главе (том + номер), появившейся на втором сайте. Ключи прочитанного
остаются привязанными к источнику; при достоверной связи уже прочитанный
номер подавляет повторное оповещение без переноса отметок в другую версию.
Фактическая дата загрузки сохраняется только если её отдал сам источник.
Прежде чем уведомлять о главе, проверяется публичный HTTPS-список страниц.
Неуспех одной площадки не стирает baseline и не блокирует другую.
Проверка не меняет активную главу и позицию. Старые уведомления с поддерживаемого
сайта могут открывать соответствующую главу при сохранённой связи.

WorkManager использует один периодический запрос на приложение с минимумом и
периодом **15 минут**. Все старые сохранённые интервалы (включая 30/60/180/360)
переводятся на 15 минут: отдельного выбора периода больше нет. Это запрос
расписания, а не обещание доставки каждые 15 минут: Doze, батарея и отсутствие
сети могут задерживать работу. Настройки читаются без межизолятного кеша;
библиотека перечитывает SharedPreferences перед сохранением, чтобы учитывать
изменения из WorkManager и не возвращать устаревший выбор источника.

Офлайн-регрессии находятся в `active_source_progress_test.dart`,
`chapter_checker_test.dart`, `chapter_alert_opt_in_test.dart`,
`source_integration_test.dart` и `qa_layout_test.dart`. Проверки Flutter,
статический анализ и debug APK должны выполняться в доверенном CI; проверка
уведомлений/жестовой навигации на устройстве остаётся необходимой.


## Умная фоновая проверка (без VPS)

WorkManager остаётся единственной плановой Android-задачей (попытка запуска
раз в 15 минут без гарантии точного времени). Для экономии запросов
**только фоновые** проверки используют локальное расписание по каждому
произведению/источнику: «читаю» — не чаще 30 минут, «в планах» — 6 часов,
«прочитано» — 24 часа. Исключённые и просмотренные произведения остаются
исключёнными, как прежде. Текущая реализация обходит главные страницы глав
только у источников, срок проверки которых наступил; полный просмотр
каждой главы не выполняется. При недоступной главе она не отмечается прочитанной.

Время последней *попытки* обращения к источнику сохраняется локально и
отдельно для гостя и каждого Firebase-профиля; не синхронизируется с
Firestore, не изменяет позиции чтения, статус или источник. После ошибки
следующая автоматическая попытка идёт по расписанию статуса, а ручная проверка
в «Уведомлениях» остаётся полной и немедленной. При запуске и возвращении
в приложение выполняется догоняющая фоновая проверка только просроченных
источников. В настройках уведомлений выводится время последнего успешного
запуска проверки и количество проверенных источников; время публикации
не следует путать со временем проверки. Android может задерживать WorkManager,
поэтому время уведомления не гарантируется. Нового сервера или FCM не требуется.
