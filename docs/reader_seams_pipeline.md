# Швы и нагрузка декодирования после PR #130

База — установленный коммит `22c5541fff07ec1f771187606cdd9ded4719db71`, он же main
на старте задачи. PR #130 изучен в объединённом виде. Эта работа не переписывает
приложение и не меняет источники, библиотеку, SQLite, account guards или signing.
Физического Pixel 8 Pro / Android 17 здесь нет.

## Воспроизведение до исправлений

[CI регрессионного коммита cdf29ac](https://github.com/Vetal12350/SenReader/actions/runs/41639571621):
статический анализ без ошибок, 340 тестов прошли, 3 новых регрессии упали.

| Проблема | Подтверждённая причина и измерение |
| --- | --- |
| Светлая линия | `_rememberHeight` игнорирует изменение менее одного logical px. После обновления URL старая высота 617.7606177606177 остаётся вместо 617.4807197943445: лишние 0.279897966 logical px ≈0.84 physical px при DPR 3. `BoxFit.fitWidth` сохраняет пропорции рисунка, но не заполняет слишком высокий box. На белом фоне появляется пустая строка. |
| Микрофризы: лишняя работа | ScrollablePositionedList 0.3.8 использует cache extent минимум два экрана. Image widgets из этой области запускают свои ImageStreams независимо от лимита двух geometry probes. Для 200 коротких strips при 10 видимых стартовало 27 image loads/decodes. Это подтверждённая лишняя работа, а не измеренное время frame jank Pixel. |
| Повторная загрузка/overdecode | Видимая плитка брала decode width из MediaQuery, prefetch — из LayoutBuilder. В reader pane шириной 400 внутри окна 800 получили одновременно hints 800 и 400. ResizeImage использует размер в cache key: реальные провайдеры могут создавать разные cache entries/декодирования для одной картинки. |

Pixel-сэмпл в первой регрессии: полностью непрозрачные тёмные исходники
дали `[16,16,16,255]`, `[16,16,16,255]`, **`[255,255,255,255]`**, затем снова
тёмные строки. В исходных синтетических bitmap белой/прозрачной кромки нет.
Это доказывает renderer/layout-механизм, а не белую полосу в файле.

Четыре обычных стыка с правильной геометрией **прошли ещё до исправлений**:
physical widths 400/537/1344/1080, DPR 1/1.25/3/2.625, в том числе дробные
позиции стыка. Простая гипотеза «любая дробная высота создаёт щель» не подтверждена.
Округлять все высоты, перекрывать соседние изображения или резать края не требуется.

Для конкретной главы пользователя нужен её URL/номера страниц или оригинальные
файлы. Они пока не предоставлены, поэтому именно её CDN-изображения не проверены.
Наличие других исходных белых краёв либо Android/Impeller-специфического дефекта
не исключается. В тестах отдельно сохраняется настоящая белая строка исходника:
исправление не должно закрашивать оригинальную манхву.

## Минимальные изменения

1. Кеш геометрии игнорирует только погрешность double порядка 1e-12, а не целый
   logical pixel. После retry, повторной активации и изменения decode/viewport
   размера intrinsic ratio измеряется заново. Полный bitmap рисуется с исходным
   соотношением сторон, без перекрытия, дополнительной обрезки или растяжения.
2. Visible image и prefetch получают одинаковый decode hint из фактической
   ширины reader × DPR, с прежним максимумом 1600. Это устранение oversampling
   узкого viewport; произвольного уменьшения качества ради FPS нет.
3. Размеры ленивых tiles по-прежнему доступны списку, но пиксели загружаются лишь
   для видимых страниц и ограниченного соседнего окна ReaderPrefetchPolicy.
   Per-page ValueNotifier переключает Image widget без rebuild всего reader.
   Сам layout списка не мигрирует и не теряет свои indexed navigation/anchors.
   Запросы обновления окна объединяются: неизменное окно не планирует работу
   на каждом scroll pixel. Новое окно явно запрашивает frame даже после остановки.
4. Дальняя кешируемая плитка имеет настоящий loading indicator, замороженный
   TickerMode, без ImageStream/декодирования. При входе в окно активация происходит
   сразу на ближайшем frame, без нового таймера или искусственной паузы.
   Ошибки активных страниц и retry UI сохраняются, а таймер невидимого retry
   отменяется. Вход обратно в окно использует обычный Flutter ImageCache.
5. Лимит prefetch, HTTP headers, обработка ошибок источников и качество фильтра
   сохранены. Видимые запросы необходимы читателю и не приравниваются к двум
   speculative tasks. Уже начатый NetworkImage HTTP не считается отменённым при
   снятии listener; ограничения/предупреждения PR #130 остаются действующими.

Новые состояния route-local: они не записываются в историю/профили/Firestore.
Данные прогресса и read/unread записываются прежним кодом с прежними UID guards.
Режим fit-height тоже обновляет окно активации, хотя geometry prefetch ему не нужен.
Существующая геометрия и idle anchor correction из PR #130 сохранены.

## Проверки и измерения

- Pixel-проверки стыков на указанных DPR/масштабах и разных scroll alignments.
- Точная геометрия и пиксели после малого изменения intrinsic ratio при URL refresh.
- Белая кромка в исходнике остаётся видимой, тёмный исходник не получает белый шов.
- 200 коротких strips: число image starts ограничено видимыми + небольшим окном;
  тест выводит `ReaderShortStripFixture visible=... imageStarts=...` для сравнения.
- Быстрые переходы вперёд/назад, повторное открытие, cache hit без нового decode
  страницы, сохранение индекса/источника/read markers, fit-height после дальнего jump.
- Полный прежний suite, включая задержки готовности кадров, 3000–12000px,
  late geometry, drag, eviction, ошибки/retry, rotation, chapter append, UID/гостя.

`flutter analyze --no-pub --no-fatal-infos --no-fatal-warnings` добавлен в PR CI
после pub get. Ошибки блокируют CI; унаследованные lint infos/warnings печатаются
и не скрываются. Массовый stylistic rewrite соседнего кода не выполняется.
Локальный cloud script остановился до Flutter: загрузка Dart SDK заблокирована
ошибкой `curl: (7) Failed to connect to proxy port 8080 ... Could not connect to server`.
Поэтому Flutter-тесты, анализ и Android compile проверяются в GitHub Actions.

## Проверка на Pixel 8 Pro / Android 17

Это не измерение CPU/GPU ms или RAM на телефоне. Image starts в контролируемом
стенде показывают объём работы; реальные transport/codec/raster timings зависят
от файлов, CDN, устройства и backend. Все микрофризы устранёнными не объявляются.

После проверки PR измерить profile mode на тех же главах/настройках, отдельно
cold/warm cache и медленную сеть. Использовать существующий флаг PR #130:

```sh
flutter run --profile --dart-define=SENREADER_READER_TRACE=true --dart-define=SENREADER_FRAME_BUDGET_US=8333
adb logcat -s flutter
```

Проверить фактические 120 Гц. Выполнить одинаковые проходы вниз/вверх, переход
главы, возврат, поворот и reopening; выйти из reader для JSON `SenReader.ReaderFrames`.
Сравнить UI/raster p95, over-budget frames, root rebuilds и cache bytes. Оценка
missed vsync не равна фактическим SurfaceFlinger dropped frames. При необходимости
собрать Perfetto FrameTimeline/GC/texture upload и `dumpsys gfxinfo`.

Для шва сохранить оригинальные два изображения и сравнить их крайние строки
без ресайза с screenshot стыка в светлой/тёмной теме. Большие исходные промежутки
между панелями не удаляются. На Impeller/Vulkan проверить дробные scroll offsets
и источники с различным кодированием/прозрачностью; software pixel-тест не заменяет
GPU-тест Pixel. Остаточные риски: первый неизвестный размер, cache eviction,
codec/GPU stalls длинных bitmap и латентность при быстром входе в холодное окно.

Схема SQLite, источники, applicationId и подпись не меняются. В main ReManga уже
удалён как активный адаптер; его исторические записи/прежняя обработка сохранены.
PR остаётся draft. Merge и публикация нового APK требуют проверки и подтверждения
владельца; workflow release job на PR не запускается.
