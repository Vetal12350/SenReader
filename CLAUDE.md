# SenReader — заметки для Claude Code (в том числе облачных сессий)

Сначала прочитайте [AGENTS.md](AGENTS.md): требования владельца и безопасность данных там главнее всего.
Ниже — то, что выяснено замерами на реальном устройстве и чего не видно из кода.

## Как устроен выпуск

| Ветка | Что происходит | Кто получает |
|---|---|---|
| feature-ветка → PR | CI: тесты + debug-сборка | никто |
| `beta` | CI подписывает APK → предрелиз **`beta-latest`** (`SenReader-beta.apk`) | владелец, для проверки на телефоне |
| `main` | CI подписывает APK → релиз **`qa-latest`** (`SenReader-latest.apk`) | **все пользователи** (репозиторий публичный) |

- Мерж в `main` = публичный релиз. Делайте его только после зелёного CI и явного «да» владельца в текущей задаче.
- Чтобы владелец проверил изменения до релиза: влейте feature-ветку в `beta` и сделайте push. Через ~10 минут
  `SenReader-beta.apk` появится в релизе `beta-latest`; владелец ставит его поверх, данные сохраняются.
- versionCode в CI = номер запуска + 1000, поэтому каждая CI-сборка новее предыдущей и ставится поверх.
  Локальные сборки ≤ 999 не публиковать.
- Подпись — ключ владельца из секретов GitHub Actions. В облаке и в репозитории ключа нет и быть не должно;
  APK с другой подписью не встанет поверх установленного, а удаление приложения стирает библиотеку.

## Инструменты

- Flutter **3.47.9** (закреплён в CI и `scripts/codex_cloud_test.sh`). На 3.50 сборка APK ломается:
  новый шаблон Android/AGP 9 и `file_picker` 11. Не обновлять без отдельной проверки сборки.
- Тесты: `bash scripts/codex_cloud_test.sh` или `flutter test` (474+ тестов, все должны проходить).
- `pubspec.lock` закоммичен; не обновляйте зависимости заодно с другой работой. `permission_handler`
  закреплён на ^12 (13.x требует compileSdk 37).
- Папка `android/` генерируется (`flutter create` + `scripts/prepare_android.py`) и в Git не хранится.
  Манифест, разрешения, иконки, `android.builtInKotlin=true` и foreground-тип `dataSync` задаёт `prepare_android.py`.

## Что выяснено о плавности ридера (Pixel 8 Pro, 120 Гц)

Причина большинства фризов — **общий главный поток**: во Flutter 3.47 UI-изолят приложения и фоновый
движок WorkManager выполняют Dart в главном потоке Android, отключить это нельзя
(флаг `DisableMergedPlatformUIThread` роняет приложение при запуске). Поэтому во время чтения в главном
потоке не должно происходить ничего тяжёлого. Уже сделано:

- `ReaderActivity` (`lib/data/reader_activity.dart`): счётчик открытых ридеров + файл-метка для других изолятов.
  Проверки глав пропускаются/прерываются, пока открыт ридер; `ReaderDeferral` откладывает облачную синхронизацию.
- Главный экран не опрашивает inbox под ридером.
- Глава заранее скачивается на диск (`PageDiskCache`), страница из файла идёт прямо в декодер
  (`ImmutableBuffer.fromFilePath`), высоты страниц берутся из заголовков файлов (`image_header.dart`),
  несколько страниц декодируются заранее, кеш картинок 320 МБ только пока открыт ридер.

Как измерять (нужен телефон с adb — в облаке недоступно):
- Сборка с `--dart-define=SENREADER_READER_TRACE=true` пишет в logcat `SenReader.ReaderFrames`
  (при выходе из главы), `SenReader.SlowFrame` и `SenReader.FrameGap` с событиями ридера рядом.
- Истина о видимых рывках — `adb shell dumpsys SurfaceFlinger --timestats -enable/-clear/-dump`,
  гистограмма `present2present` слоя SenReader. Замер Flutter-кадров не видит паузы между кадрами.
- Для причин пауз — Perfetto (`trace_processor_shell`) по главному потоку процесса.
- Последний результат: ~7 видимых рывков 25–70 мс на 1000 кадров, 0 потерянных. Возможное улучшение:
  применять высоты из заголовков пакетом по мере скачивания (сейчас только при остановке прокрутки).

## Уведомления о новых главах

- WorkManager-проверка раз в час, foreground-сервис `dataSync`, бюджет 6 мин; только сеть, без условия батареи.
  Проверка при открытии приложения — 120 с, в UI-потоке, через 20 с после старта и не при открытом ридере.
- Проверяются только книги со статусом «Читаю»; первый скан источника — молчаливая база (без уведомлений).
- Пользователь должен выдать исключение из оптимизации батареи (плитка в настройках уведомлений).
- Надёжность ночных фоновых запусков на устройстве ещё **не подтверждена** окончательно
  (`adb shell dumpsys jobscheduler`, logcat `ChapterScan`).

## Открытые идеи

- Лимит кеша картинок в ридере сделать зависимым от памяти устройства (сейчас фиксированные 320 МБ).
- Высоты страниц из заголовков применять пакетом по мере скачивания главы.
