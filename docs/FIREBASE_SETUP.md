# SenReader: Firebase for a small private group

Optional Google/email sign-in and per-user Firestore sync. Without Firebase
build configuration the app remains fully local and displays a setup note in
Settings. Do not put a service account or Firebase Admin SDK key in the APK.

1. Open https://console.firebase.google.com/ and create a Firebase project.
   Start on Spark (free), and disable Analytics if not needed.
2. Register an **Android** app with package ID `app.senreader.senreader`
   (the exact `applicationId` generated by `flutter create --org app.senreader`).
   Register SHA-1 and SHA-256 for the **release signing certificate** used by
   the QA release. Google sign-in requires Android certificate registration.
3. Enable **Authentication → Sign-in method → Email/Password and Google**.
   In the Google provider, choose a project support email. Copy the **Web
   OAuth Client ID**. Enable Cloud Firestore and select a suitable region.
4. Deploy the repository's `firestore.rules` to this project. Do not use test
   mode with permissive public rules. Example: `firebase deploy --only
   firestore:rules --project YOUR_PROJECT_ID`.
5. Supply the following **public client identifiers** as Dart defines in the
   build (or GitHub repository Variables and build arguments):
   - `SENREADER_FIREBASE_API_KEY`
   - `SENREADER_FIREBASE_APP_ID` (Android Firebase app ID)
   - `SENREADER_FIREBASE_PROJECT_ID`
   - `SENREADER_FIREBASE_SENDER_ID`
   - `SENREADER_GOOGLE_WEB_CLIENT_ID` (Web OAuth client ID)
   These values are not administrator secrets. Firestore rules enforce access.
6. Install the new, correctly signed APK **over** the current SenReader. Do
   not uninstall, change application ID, or rotate the release signing key.
7. Test with two email accounts on separate phones. Verify registration,
   confirmation email, Google login, password reset and linking, local guest
   data separation, restoration, cloud update and deletion tombstones.

## Important behavior

* Guest libraries retain the legacy `senreader.library.v1` storage.
* Signed-in accounts use their own device-local storage. Cloud sync activates
  for verified emails. Neither logging in nor logging out deletes guest data.
* **Import guest library** in Settings explicitly if desired. Existing
  account titles remain untouched by this import.
* A book is synced independently and deleted items use tombstones.
* When two offline devices modify the **same** book, the last device timestamp
  wins. Device clock skew can affect conflict results; take a backup before
  migration and avoid simultaneous edits during initial rollout.
* Cover and page images never enter Firestore; only reader metadata and
  reading history do. Friends cannot read each other's libraries under rules.
* Firebase client settings and SHA registrations are external provisioning
  tasks. No real account can sign in until they are configured.
* The Android wrapper is regenerated by GitHub Actions. No permanent
  `google-services.json` is required because FirebaseOptions are provided
  explicitly in Dart, and `google_sign_in` receives Web serverClientId.
  For complex OAuth providers use `flutterfire configure` later.
